# Flutter UI Engineer

Use this skill for UI work inside this HR employee system.

## Required Workflow

1. Read `DESIGN.md` before any UI edit.
2. Find the widget that actually renders the visible element.
3. Do not stop at changing `AppColors`; verify the visible screen uses the change.
4. Use `ThemeData`, `ColorScheme`, and Material 3.
5. Use shared widgets and design tokens for repeated UI.
6. Preserve Arabic and RTL behavior.
7. Do not change business logic, controllers, services, models, Appwrite, permissions, routing, or database behavior.
8. Do not import code from `design_references/Best-Flutter-UI-Templates`.
9. Use that repository only for visual inspiration.
10. Rebuild ideas with modern Flutter APIs.
11. Avoid direct colors, random padding, random radius, and one-off card styles inside screens.
12. Run `dart format` and `flutter analyze`.
13. Visually verify the changed screen, including responsive sizes when possible.

## UI Rules

- Prefer calm enterprise layouts over decorative or marketing layouts.
- Use semantic colors for meaning only.
- Keep cards consistent and avoid nested cards.
- Use Cairo and centralized text styles.
- Keep touch targets comfortable.
- Make loading, empty, and error states visible and polished.
- Do not claim completion until the actual screen has been redesigned and verified.
